# Project Atlas 시작 안내

이 문서는 저장소를 다시 열었을 때 가장 먼저 읽는 한국어 안내서다. 상세한
제품 계약은 `PRD.md`, 기술 계약은 `docs/TECH_SPEC.md`가 기준이며, 이 문서는
그 둘을 대체하지 않고 현재 결정의 맥락과 읽는 순서를 연결한다.

## 한 문장으로 설명하면

Project Atlas는 **정리되지 않은 호기심을 사용자가 승인한 학습 질문으로
바꾸고, 바로 시작할 수 있는 작은 행동과 검증 가능한 증거까지 이어 주는
시스템**이다.

사용자는 좋은 질문이나 검색어를 준비할 필요가 없다. 예를 들어 다음처럼
입력해도 된다.

> Kafka가 궁금하고 큰 시스템도 배우고 싶은데, retry나 중복 같은 말을
> 들어도 내가 정확히 뭘 모르는지는 모르겠다.

Atlas는 원문을 그대로 보존하고, 방향을 실제로 바꿀 수 있는 질문만 한 번에
하나씩 묻는다. 최대 세 번의 답을 바탕으로 `Learning Brief`를 제안하고,
사용자가 고쳐서 명시적으로 승인하면 30분 안에 끝낼 첫 행동 하나를 준다.

## 왜 이 형태를 선택했나

처음 검토한 두 극단에는 각각 문제가 있었다.

- 범용 AI 학습 운영체제는 멋져 보이지만 일반 챗봇이나 커리큘럼 생성기와
  구분되기 어렵고, 너무 많은 분야를 얕게 다룰 위험이 있다.
- 장애 실습 플랫폼만 만들면 기술 포트폴리오는 강해지지만, 사용자가 애초에
  무엇을 배워야 할지 모르는 문제를 건너뛴다.

따라서 제품의 중심은 `모호함 -> 승인된 질문 -> 행동 -> 증거`로 두고, 첫
전문 분야를 백엔드 시스템과 신뢰성으로 좁혔다. 첫 심화 활동은 나중에 만들
`응답 유실로 인한 중복 결제` 장애 실습이다. 이 조합이 실제 사용자에게
가치가 없는 것으로 측정되면 PRD의 중단·전환 규칙에 따라 과감히 좁히거나
폐기한다.

## 지금 완성된 것과 아직 없는 것

현재는 **M0: 저장소와 계약**까지 완료된 상태다.

완성된 것:

- 제품 가설, 성공 지표, 비목표, 전환 조건
- 현재와 미래를 분리한 기술 설계
- Spring Boot API, React 웹, PostgreSQL 로컬 환경
- 테스트, 모듈 경계 검사, CI, 전체 검증 스크립트
- AI가 코드를 많이 작성해도 소유권을 잃지 않기 위한 작업 규칙

아직 구현하지 않은 것:

- Brain Dump 저장 API와 화면 동작
- 명확화 질문, Learning Brief, 승인 상태 머신
- 실제 AI 모델 연동
- Question Map, 지식 검색, RAG
- 장애 실습, 코드 실행 Runner
- 인증, 실시간 협업, Kafka, Kubernetes

웹 첫 화면은 제품 방향을 확인하는 정적 기반 화면이다. 작동하는 M1 기능처럼
보이게 꾸미지 않았다.

## 현재 구현할 최소 조각 M1.1

M1 전체를 한 번에 만들지 않는다. 현재 활성 조각은 **M1.1 Brain Dump
capture**이며, 정리되지 않은 입력을 원문 그대로 저장하고 조회하는 한 행동만
완성한다. 실패 후 같은 내용을 재시도해도 중복이 생기지 않고, 입력을 고치면
새 요청으로 취급한다. 정확한 계약은 `docs/M1_CAPTURE_SLICE.md`에 있다.

명확화 질문, fake 제안기, Brief, 승인과 다음 행동은 M1.1에 포함하지 않는다.
저장 성공이 앞으로 추가될 해석이나 AI 호출의 성공 여부에 종속되지 않게 하기
위해서다.

## 이후 완성할 제품 마일스톤 M1

M1의 끝은 다음 한 줄이다.

> 사용자가 정리되지 않은 생각을 입력하고, 최대 세 질문에 답하고, 자신이
> 의도한 내용이라고 느끼는 Brief를 승인한 뒤, 30분짜리 행동 하나를 본다.

흐름은 다음 여섯 상태만 가진다.

```text
입력 -> 명확화 -> Brief 검토 -> 승인 -> 다음 행동 -> 이어하기
```

M1에서는 결정론적 fake 제안기를 먼저 쓴다. 모델 키, 비용, 네트워크, 응답
편차 없이 제품의 상태 전이와 사용자 가치를 먼저 검증하기 위해서다. 실제
모델은 M1을 직접 사용해 평가 예시가 쌓인 뒤 M1.5에서 교체 가능한 어댑터로
연결한다.

## 현재 구조

```text
브라우저
  -> React + TypeScript
  -> Spring Boot 모듈러 모놀리스
  -> PostgreSQL
```

분산 시스템을 배우는 프로젝트지만 처음부터 마이크로서비스로 나누지 않는다.
제품 가설이 틀렸을 때 쉽게 지울 수 있고, 한 사람이 데이터와 트랜잭션 경계를
끝까지 설명할 수 있는 구조가 먼저다. Kafka, Runner 분리, Kubernetes 같은
기술은 `docs/TECH_SPEC.md`의 관측 가능한 도입 조건을 만족할 때만 추가한다.

## AI와 사람의 권한

- AI는 질문, Brief, 다음 행동, 피드백을 **제안**할 수 있다.
- 사용자는 자신의 의도와 Brief를 **승인**한다.
- 애플리케이션만 제품 상태를 **전이**한다.
- 테스트 가능한 보장은 결정론적 검증기가 **판정**한다.

AI가 승인, 학습 완료, 실습 통과를 스스로 결정하면 안 된다. 사용자의 원문을
AI 요약으로 덮어쓰거나, 근거 없는 숙련도 점수를 표시하는 것도 금지한다.

## 이 프로젝트로 공부하는 방법

한 마일스톤에서 낯선 핵심 개념은 하나만 도입한다.

- M1: aggregate 상태 머신과 트랜잭션 경계
- M1.5: 실패할 수 있는 외부 AI 작업의 내구성과 멱등성
- M2: 관계형 데이터에서 버전이 있는 질문 관계 표현
- M3: 결정론적 장애 주입과 불변식 테스트
- M4: 프로세스 격리와 reconciliation
- M5: 멀티테넌트 보안과 실제 운영

코드 양을 이해의 기준으로 삼지 않는다. 중요한 변경을 합치기 전에 다음을
설명할 수 있어야 한다.

1. 어떤 사용자 행동이 달라졌는가?
2. 상태는 어디에 있고 트랜잭션은 어디서 끝나는가?
3. 중간에 프로세스가 죽으면 무엇이 남는가?
4. timeout, 중복 요청, retry 때 무슨 일이 일어나는가?
5. 어떤 테스트가 핵심 불변식을 증명하는가?
6. 이 변경을 어떻게 되돌리거나 삭제하는가?

설명이 안 되면 문서를 더 길게 만드는 대신 구현을 작게 줄인다.

## 바로 실행하기

요구 도구는 Java 21, Node.js 22.17 이상(Node 22 또는 24), pnpm 10,
Docker Desktop이다.

```powershell
docker compose up -d --wait postgres
pnpm install --frozen-lockfile
.\scripts\verify.ps1
```

기본 PostgreSQL 주소는 `localhost:55432`다. 다른 로컬 프로젝트가 흔히 쓰는
5432와 충돌하지 않도록 호스트 포트만 바꿨고, 컨테이너 내부 포트는 5432를
유지한다.

개발 서버 실행 명령은 `README.md`에 있다.
